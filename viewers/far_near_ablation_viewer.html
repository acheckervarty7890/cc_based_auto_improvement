Far / near removal ablation — does deleting red-team data far from the eval distribution help?

Probe: harmful_to_human on google/gemma-3-27b-it layer 32, architecture linear_then_softmax. Eval = the four eval_dataset_hu_ha splits, full (866 rows). Two runs of the same question, 10 random-start iterations per arm, train/val split seed held at 42 throughout.

  • run A — full: all red-teaming data
  • run B — full: red-teaming data after removing truncated examples and keeping only intact pairs
  • near: dropping 10% of near cluster samples
  • far: dropping 10% of far cluster samples

4 · How the data differs between the two analyses

Same source, different corpus. Both start from redteam_postprocessed_iter3.jsonl — the 878 rows that actually trained probe_iter3, 439 attacker originals plus one LLM-generated contrastive counterpart each, exactly 439 positive / 439 negative. Run B then drops 142 of them: 72 truncated rows (conversations cut at get_activations' hard 1024-token cap, whose pooled vector is a mean over a truncated prefix) and 70 orphaned halves whose contrastive partner did not survive. What remains is 736 rows = 368 intact pairs. So run B's full baseline is a different probe, not a cleaner version of the same one — and those 142 excluded rows are the long tail of the corpus (mean 618 tokens, 51% at the cap).

Different clustering. Run A used a single k-means at k=8 on the red-team side (eval k=3). Run B used consensus clustering — several k × seeds × random subsamples reduced through a co-association matrix, average-linkage, cut by silhouette — at k=9 (eval k=7), with the partition frozen in git so the cloud box could not silently re-cut it. Distance is the same in both: minimum cosine from a row (or a cluster centroid) to its nearest eval-cluster centroid.

Different arm rules. Run A's far arm is two whole clusters, c4 (23) + c6 (68) = 91 rows (10.4% of 878). Run B's is c6 whole (23) plus the 51 farthest rows of c1 by per-row distance = 74 rows (10.1% of 736). The near sides are not comparable at all: run A drew 91 rows from c2 and deliberately label-matched them to far, then reused that one draw across every seed — a second arm. Run B draws 10 random 74-row samples from a 234-row pool (c5 + c0, the two nearest whole clusters) at a fixed seed — a which-rows null, and one that is not label-matched: that pool is 74% positive against a 50% corpus, so those draws also shift the class prior. Neither run has a global-random arm.

Average token length by arm

full (corpus) far near

Token counts are the cached n_tokens per conversation, i.e. post-truncation (min(true_len, 1024)) — the lengths the probe actually saw. Run B rows were matched to run A's by an exact activation-vector permutation, so both columns are measured identically.

Length and truncation track the region, and only in run A. There, the far region is the short side (mean 350 tok, 1.1% truncated) while the near arm is long (mean 547 tok, 14.3% truncated, drawn from a c2 pool that is 19.5% truncated) — so in run A "how far from eval" is partly a proxy for "how long, and whether the activation was cut off at the cap". Run B removes every truncated row up front, and its two regions land at comparable lengths (371 vs 307 tok, both 0% truncated) — with both effects then sitting inside noise. That is a hypothesis the two runs are consistent with, not an established mechanism: the corpus, the clustering, the arm rule and the near-arm construction all changed at once.
